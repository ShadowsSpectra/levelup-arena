# LevelUP Arena

Игровой тренажёр переговоров на React, TypeScript и Vite.

## Локальный запуск

1. Установите актуальную LTS-версию [Node.js](https://nodejs.org/).
2. Откройте терминал в папке проекта.
3. Выполните `npm install`.
4. Выполните `npm run dev`. Эта команда поднимает и сайт, и локальные `/api/ai` маршруты.
5. Откройте адрес, который появится в терминале (обычно `http://localhost:5173`).

## Команды

- `npm run dev` — запустить приложение для разработки.
- `npm run typecheck` — проверить TypeScript.
- `npm test` — проверить правила Training и прогрессии.
- `npm run build` — собрать production-версию.
- `npm start` — запустить единый production Node-сервер (сайт + API).
- `npm run preview` — локально открыть собранную production-версию.

## AI Settings для Arena

На главной роли или в Arena нажмите **AI Settings**. Выберите `OpenAI-compatible`, введите доверенный Base URL провайдера (обычно адрес с `/v1`), свой API Key и точное название модели у провайдера. Нажмите **Проверить подключение**, затем **Сохранить настройки**. Проверка отправляет короткий запрос провайдеру и может расходовать небольшой объём токенов.

Позже нажмите **Изменить настройки**, чтобы изменить конфигурацию. Если поле ключа оставить пустым, текущий BYOK-ключ сохраняется в памяти вкладки. Можно явно вернуться к AI приложения. Во время ожидания ответа Arena показывает, что оппонент печатает; при сбое сообщает об ошибке и позволяет повторить запрос.

Браузер обращается только к `/api/ai`; внешний запрос выполняет сервер. Необязательный BYOK хранится только в памяти вкладки и передаётся только с её запросами; обновление страницы забывает его. Ключ не попадает в localStorage/sessionStorage или Git. Серверный ключ по умолчанию никогда не возвращается браузеру. Автоматического переключения между BYOK, AI приложения и Mock нет. При ошибке переговоры сохраняются для повторной отправки/оценки.

## Production: один Node-сервис

Требуется Node.js 22.12+ (или 24). В корне проекта:

```sh
npm run build
npm start
```

Откройте `http://localhost:3000`; проверка доступности — `http://localhost:3000/health` (без AI-запроса). `PORT` переопределяет порт; сервер слушает `0.0.0.0`.

Для AI приложения задайте серверные переменные окружения (хостинг передаёт их процессу), либо локально создайте игнорируемый Git файл `.env`:

```dotenv
AI_PROVIDER=openai-compatible
AI_BASE_URL=https://api.mistral.ai/v1
AI_API_KEY=replace-with-your-secret
AI_MODEL=replace-with-an-available-model
PORT=3000
```

Все четыре AI-поля задаются вместе. Без них сайт и `/health` работают, но для Arena нужен BYOK. `npm start` читает необязательный `.env`; не используйте `VITE_` для секретов. `.env` нельзя коммитить. В production Base URL должен быть HTTPS и входить в явный allowlist: Mistral, OpenAI, Groq, OpenRouter. `AI_BYOK_ALLOWED_BASE_URLS` при необходимости заменяет список (адреса через запятую). Production не разрешает localhost. `/check` не сохраняет настройки.

Сборка создаёт публичный `dist` и приватный `dist-server/ai.mjs`. Запускайте Node-сервис, а не только статический хостинг. Не публикуйте `dist-server` или `server/content`: Node выдаёт файлы только из `dist`. Для публичного размещения необходим HTTPS на входе через хостинг/reverse proxy.

Demo-защита `/api/ai/*`: максимум 128 000 байт тела, 60 запросов/минуту на IP, 300/минуту на процесс; одновременно максимум 2 AI-запроса на IP и 6 на процесс. Ответ ограничения — 429 с `Retry-After: 60`, большого тела — 413. Состояние ограничений только в памяти одного процесса, после рестарта сбрасывается; это не полноценная защита платного API от злоупотреблений. `/health` и статические файлы не занимают AI-слоты.

По умолчанию IP берётся из соединения, forwarded-заголовки игнорируются. Только за доверенным reverse proxy задавайте `TRUST_PROXY_HOPS` числом доверенных прокси (например, `1` для одного). Без этого посетители за одним proxy могут разделять IP-лимит. Не включайте доверие к proxy при прямом публичном доступе к Node. Ограничьте бюджет/квоту ключа у провайдера для публичного demo.

## Структура `src`

- `pages` — страницы приложения;
- `components` — переиспользуемые UI-компоненты;
- `config` — настройки XP, уровней, Energy и ролей;
- `content` — вопросы и сценарии;
- `services` — игровая логика, хранение и будущие интеграции;
- `state` — состояние пользователя;
- `styles` — общие стили.

## Training-контент

Тестовые задания находятся в `src/content/questions.json`. Каждое задание —
отдельный JSON-объект с уникальным `id`. Чтобы временно скрыть задание, установите
`"active": false`.

Поле `correctAnswer` содержит индекс правильного варианта и начинается с нуля:
`0` — первый ответ, `1` — второй, `2` — третий, `3` — четвёртый. После редактирования запустите
`npm run typecheck` и `npm run build`.

Приложение получает контент через интерфейс `QuestionSource` в
`src/content/questionSource.ts`. В будущем локальную реализацию можно заменить
источником из облачной таблицы, не меняя Training UI и Training Engine.

## Прогрессия

Пороги уровней и правила Energy находятся в `src/config/progression.ts`.
Начисление XP и streak рассчитываются в
`src/services/progression.ts`, отдельно от Training UI. XP и Arena Unlock
принадлежит выбранной роли; Energy и streak общие. Arena доступна сразу после выбора роли.

Данные прогрессии сохраняются локально в браузере под ключом
`levelup-arena:progression-v1`. Авторизации нет; BYOK AI-настройки хранятся отдельно в памяти вкладки.
